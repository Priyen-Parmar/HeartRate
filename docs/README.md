# OptiPulse documentation

| Document | Read it when you want to... |
|---|---|
| [EXPLAIN.md](EXPLAIN.md) | **start here as a new contributor.** Learn how the system works and how the code is organised: the data flow from frame to number, every module, the training and evaluation pipeline, the design rules, and common tasks. |
| [USAGE.md](USAGE.md) | install and run the app on Windows, macOS or Linux. Covers every command-line option, the on-screen elements, the CSV log, raw recording and replay, testing against a reference device, and troubleshooting. |
| [METHOD.md](METHOD.md) | read the method as a paper would present it: contributions and their origins, evaluation protocol, limitations. |
| [../results/RESULTS.md](../results/RESULTS.md) | see every result table and figure. It is generated by `pipeline/make_report.py`; do not edit it by hand. |
| [FUTURE_WORK.md](FUTURE_WORK.md) | find out what is unsolved (weak pulse on real webcams) and what to do next, including candidate datasets. |
| [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) | trace the chronological lab notebook: what was tried, measured, fixed or rejected, and why. |
| [report/](report/) | read the final UGP report (`OptiPulse_UGP_Report.pdf`) and its LaTeX source. |
| [presentation/](presentation/) | get the project presentation slides (`.pptx` and `.pdf`). |

**Suggested reading order**

* **Users:** [USAGE.md](USAGE.md).
* **New developers:** [EXPLAIN.md](EXPLAIN.md), then [USAGE.md](USAGE.md), then the code.
* **Reviewers:** [METHOD.md](METHOD.md), then [RESULTS.md](../results/RESULTS.md).
* **Whoever continues the research:** [FUTURE_WORK.md](FUTURE_WORK.md), then
  [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) §8–14.

**Building the report PDF.** The LaTeX source loads its figures from `results/figures/`, so compile it
from the repository root:

```bash
pdflatex -output-directory docs/report docs/report/OptiPulse_UGP_Report.tex   # run twice for references
```
